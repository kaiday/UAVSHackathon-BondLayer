03 · THE SOLUTION

BondLayer: publish · prove · decode

A merchant-side layer that serves the catalogue as UCP already expects it — plus a signed extension, org.bondlayer.benefit_value, that turns policy prose into typed, verifiable, priced records on the same call an agent already makes. Nothing is installed on the agent side.

🔌

PUBLISH

Speak the Universal Commerce Protocol out of the box. Catalogue CSV in → normalised, agent-ready catalog.search / lookup out. Capability negotiation: an agent that doesn't know us gets plain, conformant UCP.

🔏

PROVE

Returns, warranty, repairs, member value become signed records (ES256 over canonical JSON) with a declared value ceiling. Unsigned claims are shown — and never credited. Keys published in /.well-known/ucp.

🧠

DECODE

An intent interpreter splits the shopper's sentence into HARD / SOFT / SERVICE / VALUES clauses and justifies each one against an attribute or a verified record — or says honestly that nothing answers it.

NOT A SHOPPING ASSISTANT — MERCHANT SIDE ONLY CONTROL = SAME SERVER, EXTENSION OFF THE SHOPPER'S POLICY NEVER LEAVES THE AGENT

04 · HOW IT WORKS · BUILT AGAINST FPT'S FIVE-STEP DESIRED OUTCOME

Receive → decode → analyse → return → close

1

RECEIVE

The agent's multi-constraint query arrives over UCP. With intent_match negotiated, the merchant receives the utterance verbatim on its own wire.

POST /{merchant}/ucp/intent/propose
2

DECODE

Deterministic parser → typed constraints. Four kinds; the bottom two have no catalogue column and must resolve against records.

interpreter/parser.py · describe.py
3

ANALYSE

Resolver cites one attribute or one verified record per clause. Bundler composes sets ("everything to start a podcast" → 5 items, one rationale).

interpreter/resolver.py · bundle/compose.py
4

RETURN

Not a SKU list — a proposal with a reason per line, an honest unsatisfied list, and signed evidence the agent can re-verify and cache.

proposals[].resolved · extensions
5

CLOSE

Agent checks out the winner citing the records it relied on; merchant re-verifies and binds the honoured ones into the order. Payment out of scope.

POST /{merchant}/ucp/checkout
AGENT SIDE KEEPS: VALUATION · WEIGHTS · CROSS-MERCHANT RANKING MERCHANT SIDE GETS: THE QUESTION, NEVER THE POLICY NO MODEL ON ANY DECISION PATH

🧪 TAMPER TESTS, NOT SLIDES

Inflate an unsigned claim → ranking does not move. Inflate a signed ceiling to $9,999 → still only a ceiling; the shopper's policy caps it. Tamper one byte of a signed record → verify fails. All three run in tests/test_invariants.py.

🔒 WHAT NEVER CROSSES THE WIRE

The shopper's valuation policy, benefit weights and the cross-merchant comparison stay in the agent. Send a shopper_policy field to checkout and the merchant answers 422 — refused, not silently read. No PII; synthetic member data only.
